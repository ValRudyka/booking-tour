# Завдання для Claude Code: сторінка туру `/tours/:id`

Гілка: `feature/frontend-public`. Якщо PR каталогу вже злитий, створити гілку з такою самою назвою від актуального `develop`.
Порядок роботи: спочатку план на затвердження, код лише після мого «ок».

Каталог `/tours` уже працює. Ця сторінка замінює заглушку `/tours/:id`, на яку ведуть картки каталогу.

## 1. Розмітка

```
┌───────────────────────────────────────────────────────────────┐
│ Шапка                                                         │
├───────────────────────────────────────────────────────────────┤
│ Каталог / Єгипет / Хургада / Назва туру        (Breadcrumb)    │
│ <h1> Назва туру                                               │
│ Coral Bay Resort ★★★★★ · Рейтинг 4.33 (12 відгуків)           │
├──────────────────────────────────────────┬────────────────────┤
│ Галерея (Image.PreviewGroup)             │ Блок бронювання    │
│                                          │ (sticky на десктопі│
│ Tabs:                                    │  фон SAND_BG)      │
│  Опис · Програма · Готель · Відгуки (12) │                    │
│                                          │ від 32 000 ₴       │
│ [вміст вкладки]                          │ Дата виїзду ▾      │
│                                          │ Місто вильоту      │
│                                          │ Ночей: 7           │
│                                          │ Вільних місць: 6   │
│                                          │ [Забронювати]      │
├──────────────────────────────────────────┴────────────────────┤
│ Футер                                                         │
└───────────────────────────────────────────────────────────────┘
```

- Десктоп: дві колонки, ліва ~2/3, права ~1/3. Блок бронювання прилипає (`position: sticky`) під час прокручування.
- Мобільний: одна колонка. Блок бронювання йде одразу після галереї, а внизу екрана фіксована панель з ціною та кнопкою «Забронювати».
- `<h1>` — назва туру. `document.title` = «Назва туру — SITE_NAME».

## 2. Вміст

### Заголовна частина
- `Breadcrumb`: Каталог → країна → курорт → назва туру. Країна й курорт ведуть у каталог з відповідним фільтром у URL (`/tours?country_id=…`).
- Готель із зірками, рейтинг готелю й кількість опублікованих відгуків. Клік по відгуках відкриває вкладку «Відгуки». Якщо рейтинг `null`, показується «Ще немає відгуків».

### Галерея
- `Image.PreviewGroup`: велике фото й мініатюри. Перегляд на весь екран використовує вбудований `preview` від antd.
- Немає фото — та сама заглушка, що й у `TourCard` (винести в спільний компонент, якщо ще не винесена).
- У кожного фото є `alt` (назва туру або готелю).

### Вкладки (`Tabs`)
Активна вкладка зберігається в URL (`?tab=reviews`), щоб посилання на відгуки працювало.

1. **Опис**: опис туру; що включено й не включено (два списки з іконками `CheckOutlined` / `CloseOutlined`, якщо API їх повертає); тип транспорту.
2. **Програма**: `Timeline` по днях (День 1, День 2…) із заголовком і текстом кожного дня.
3. **Готель**: `Descriptions` (назва, зірки, курорт, відстань до пляжу й аеропорту, час заїзду й виїзду — лише ті поля, що є в API) і опис готелю.
4. **Відгуки (N)**:
   - Підсумок: середня оцінка готелю та кількість відгуків.
   - Список опублікованих відгуків: ім'я автора (як його віддає API, без повного прізвища, якщо API приховує), дата поїздки, оцінки (`Rate disabled`), тексти вражень, фото відгуку (мініатюри з `preview`).
   - Серверна пагінація, якщо API її має; інакше кнопка «Показати ще».
   - Порожній стан: «Ще немає відгуків. Відгук можуть залишити туристи після завершення поїздки.»
   - Фото відгуків вантажаться через ендпоінт фото з бекенду. Перевірити, що для опублікованих відгуків він відкритий гостям.

### Блок бронювання
- Ціна «від N ₴» кольором `PRICE_COLOR` (ціна за дорослого, як каже API; так і підписати: «за дорослого»).
- Вибір дати виїзду, якщо в туру кілька дат або діапазон. Минулі дати недоступні; «сьогодні» береться за київським часом, як у каталозі.
- Місто вильоту, кількість ночей, тип харчування (якщо вже є в API).
- Вільні місця. Якщо 3 або менше — `Tag` «Залишилось N місць». Якщо 0 — кнопка неактивна з поясненням «Місць немає».
- Кнопка **«Забронювати»** (primary). Сторінки бронювання й входу ще немає, тому:
  - веде на заглушку `/booking/:tourId?date=…`;
  - реальну логіку («неавторизованого спочатку на вхід, потім назад до бронювання») зробимо в наступних завданнях. Залишити в коді одне місце, де це зміниться.
- Кнопку «В обране» поки не додавати: вона потребує входу.

## 3. Стани

| Стан | Що показати |
|---|---|
| Завантаження | `Skeleton` у формі сторінки, `active={false}` |
| Тур не знайдено (404) | `Result status="404"`: «Тур не знайдено або він більше не продається», кнопка «До каталогу» |
| Тур знятий з публікації чи в архіві | Так само, як 404, якщо API повертає 404. Якщо API віддає тур зі статусом — показати `Alert` «Тур більше не продається» і вимкнути бронювання |
| Помилка API | `Alert type="error"` з кнопкою «Спробувати ще раз» |
| Помилка лише у відгуках | Решта сторінки працює; помилка показується лише у вкладці «Відгуки» |
| Режим обслуговування | Той самий компонент, що й у каталозі |

## 4. Дані та запити

- Окремі запити TanStack Query для туру й для відгуків, щоб відгуки вантажилися лише при відкритті вкладки або лічильника.
- Перехід з каталогу не повинен ламати кнопку «Назад»: повертатися в каталог з тими самими фільтрами й сторінкою.
- Ціни, рейтинги й інші суми з API приходять рядками: лише форматувати для показу, без арифметики з float.

---

## 5. Тести (у тих самих комітах, що й код)

- Сторінка показує назву, ціну «від N ₴ за дорослого» і вільні місця з мок-даних.
- 404 показує `Result` з кнопкою «До каталогу».
- `?tab=reviews` відкриває вкладку відгуків; порожній список показує текст порожнього стану.
- 0 вільних місць робить «Забронювати» неактивною з поясненням.
- Помилка відгуків не ламає решту сторінки.
