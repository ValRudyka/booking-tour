## 1. Спільні правила бекофісу

- **Бібліотеки:** antd 6 + ProComponents v3 (версія, сумісна з antd 6). Тема та палітра — ті самі, що на публічному сайті, `motion: false`.
- **Маршрути:** усе під `/office/*`, захищено `RequireAuth` з ролями персоналу. `/office` перенаправляє на першу сторінку ролі (менеджер → заявки, фінансист → транзакції, адміністратор → користувачі).
- **Розмітка:** `OfficeLayout` на `ProLayout`: ліве меню, яке будується з ролі користувача; угорі — назва сайту, «Робочий кабінет», ім'я та роль, дзвіночок сповіщень (той самий компонент, що й у клієнта), «Вийти». Посилання «На сайт» веде на публічну частину.
- **Меню за ролями** (пункти без API не показувати):

| Роль | Пункти |
|---|---|
| Менеджер | Заявки · Тури · Відгуки · Промокоди · Статистика |
| Фінансовий контролер | Транзакції · Повернення · Звіти |
| Адміністратор | Користувачі · Довідники · Налаштування · Журнал аудиту |

- **Таблиці:** `ProTable` з серверною пагінацією, сортуванням і фільтрами через параметри API; стан фільтрів і сторінки в URL. Статуси — `Tag` зі спільного словника `src/constants/orderStatus.ts`.
- **Дії, які не можна скасувати** (відхилення, повернення коштів, блокування, видалення, архівування): завжди підтвердження через `Modal`/`Popconfirm` з коротким описом наслідків. Кнопка блокується на час запиту.
- **Помилки:** 403 → `Result` «Недостатньо прав»; 409 (наприклад, заявку вже взяв інший менеджер) → `Alert` з текстом сервера й оновлення даних.
- **Адаптивність:** бекофіс розрахований на ширину від 1280 px, але на 768 px працює (таблиці прокручуються горизонтально). На телефоні — без поламаної розмітки.
- **Дані:** суми й рейтинги — рядки з API, лише форматування; дати й час — київський час.
- **Без емодзі й анімацій.**

## 2. Заявки `/office/orders` (менеджер)

`ProTable`:
- Колонки: №, клієнт (ПІБ і телефон), тур, дата виїзду, туристів, сума, статус, відповідальний менеджер, дата створення.
- Вкладки над таблицею (`ProTable` `toolbar.menu` або `Segmented`): «Нові» (ще ніхто не взяв), «Мої в роботі», «Усі». Лічильник біля кожної, якщо API його дає.
- Пошук і фільтри: номер, клієнт, статус, період створення, дата виїзду.
- Дія в рядку: «Взяти в роботу» (для нових) і «Відкрити».

## 3. Обробка заявки `/office/orders/:id` (менеджер)

```
┌──────────────────────────────────────────────┬──────────────────────┐
│ Заявка №1042  [Статус]  Відповідальний: ...  │ Дії за статусом:     │
│ ProDescriptions: клієнт, тур, дати, послуги, │ [Взяти в роботу]     │
│ промокод, сума, оплата                       │ [Підтвердити (PNR)]  │
│ Туристи: таблиця з повними паспортними даними│ [Відхилити]          │
│ Документи: список + Upload                   │                      │
│ Історія статусів: Timeline                   │ Нотатки (якщо є API) │
└──────────────────────────────────────────────┴──────────────────────┘
```

- **Взяти в роботу:** одна кнопка; якщо заявку вже взяв інший менеджер — 409 і оновлення.
- **Підтвердити:** `ModalForm` з полем PNR (формат — за правилами бекенду) і підтвердженням.
- **Відхилити:** `ModalForm` з обов'язковою причиною; попередження, що клієнт отримає сповіщення, а повернення коштів обробить фінансовий відділ (якщо так працює бекенд).
- **Документи:** `Upload` з типом документа (ваучер, квиток, страховка — із API), перевіркою типу й розміру файлу; список завантажених з можливістю завантажити й (якщо дозволено) видалити. Файли приватні — завантаження авторизованим запитом.
- **Туристи:** менеджер бачить повні паспортні дані (вони потрібні для бронювання). Не виводити їх у `console.log` і не зберігати в `localStorage`.
- **Запит клієнта на скасування:** якщо є — помітний `Alert` угорі з причиною клієнта й діями, які дозволяє бекенд.
- Кнопки показуються лише для статусів і ролей, де бекенд їх дозволяє (у плані — таблиця «статус → доступні дії»).

## 4. Тести (у тих самих комітах, що й код)

- Меню будується з ролі: менеджер не бачить «Транзакції», фінансист не бачить «Заявки».
- Клієнт, який відкриває `/office`, бачить 403.
- Таблиця заявок: вкладки й фільтри потрапляють у параметри запиту й URL.
- Дії заявки показуються лише для дозволених статусів; «Відхилити» вимагає причину; 409 показує текст сервера.
- Завантаження документа відправляє файл з правильним типом.
