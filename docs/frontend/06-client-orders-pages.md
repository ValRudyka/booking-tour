## 1. Кабінет клієнта: розмітка

`CabinetLayout` для клієнта на звичайному antd `Layout` + `Menu` (ProComponents лише в бекофісі):
- ліве меню: «Мої замовлення», «Історія подорожей» (заглушка), «Профіль» (заглушка), «Обране» (заглушка, якщо бекенд не має обраного — не показувати);
- на мобільному меню ховається в `Drawer`;
- шапка та сама, що в `PublicLayout`, з дзвіночком сповіщень.

Маршрути під `/cabinet/*`, лише для клієнта.

## 2. Мої замовлення `/cabinet/orders`

- `Table` (на мобільному — список карток): номер, тур, дати, туристів, сума, статус (`Tag` зі словника), дата створення.
- Фільтр за статусом (`Segmented` або `Select`: «Активні», «Завершені», «Скасовані», «Усі»), стан у URL.
- Серверна пагінація, якщо API її має.
- Дія в рядку залежно від статусу: «Оплатити» (веде на `/orders/:id/pay`), «Деталі».
- Порожній стан: «У вас ще немає замовлень» і кнопка «До каталогу».

## 3. Деталі замовлення `/cabinet/orders/:id`

```
┌──────────────────────────────────────┬────────────────────────┐
│ Замовлення №1042  [Тег статусу]      │ Дії (залежать від      │
│ Steps / Timeline: історія статусів   │  статусу):             │
│                                      │ [Оплатити]             │
│ Тур, готель, дати, місто вильоту     │ [Скасувати]            │
│ Туристи (паспорти частково приховані)│ [Залишити відгук]      │
│ Послуги, промокод, сума              │                        │
│ Документи: список з кнопками         │ Повернення коштів:     │
│  «Завантажити» (ваучер, квитки…)     │  статус, сума          │
└──────────────────────────────────────┴────────────────────────┘
```

- Історія статусів з API — `Timeline` з датою й часом кожної зміни (київський час).
- Документи: приватні, тому завантаження через авторизований запит (blob → збереження файлу), а не просте посилання без токена. Якщо документів ще немає — пояснення, коли вони з'являться.
- **Скасування**: кнопка лише для статусів, у яких бекенд дозволяє запит. `Modal` з полем причини та попередженням про умови повернення (текст з API або з ТЗ). Після запиту статус оновлюється.
- **Повернення коштів**: якщо бекенд повертає дані про повернення — показати статус і суму.
- 404 / чуже замовлення → `Result` 404.

## 4. Відгук `/cabinet/orders/:id/review`

Лише для замовлень, які бекенд дозволяє оцінити (завершена поїздка; архівне — лише якщо раніше було «завершено»).
- Дві обов'язкові оцінки (`Rate`) і два необов'язкові текстові поля вражень — як у бекенді.
- Фото: `Upload` списком мініатюр, до `MAX_REVIEW_PHOTOS` (10), з перевіркою типу й розміру на клієнті та показом помилок сервера.
- Підказка, що відгук публікується після модерації (якщо налаштування `review_premoderation` увімкнене — брати з API, якщо воно доступне).
- Відхилений відгук: показати причину й дозволити одну повторну подачу (`PATCH`); після другого відхилення — лише перегляд, без кнопки.
- Відгук уже є → показати його та статус модерації замість форми.

## 5. Сповіщення

## 6. Тести (у тих самих комітах, що й код)

- Словник статусів покриває всі статуси з OpenAPI-схеми (тест падає, якщо в бекенді з'явиться новий статус без перекладу).
- Список: фільтр у URL, порожній стан.
- Деталі: кнопки дій показуються лише для дозволених статусів; скасування вимагає причину.
- Завантаження документа робить авторизований запит.
- Відгук: обидві оцінки обов'язкові; понад 10 фото не додаються; другий відхилений відгук не можна подати знову.
- Лічильник сповіщень оновлюється після позначення прочитаним.
